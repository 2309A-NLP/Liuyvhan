# Agent-02 日程管家 — 优化总结

**项目名称：** 日程管家（NLP-Agent 数字人项目-日程管家任务）
**类型：** Agent/业务型（非RAG）
**端口：** 8012 | **数据库：** MySQL schedule_reminder | **LLM：** SiliconFlow DeepSeek-V4-Flash

---

## 1. 架构优化

### 当前架构
```
用户输入 → NLP解析 → 状态管理 → 意图路由 → 确认流程 → 数据库CRUD → 提醒引擎 → Web前端
```

### 四层架构
| 层次 | 组件 | 职责 |
|------|------|------|
| Web框架层 | FastAPI + uvicorn | HTTP路由、CORS、静态文件挂载 |
| NLP引擎层 | LLM调用 + 规则兜底 | 8种Intent识别、中文时间解析 |
| 状态管理层 | 6种会话状态 | 多轮对话持久化、确认/取消流 |
| 存储层 | MySQL + 连接池 | CRUD操作、到期查询 |

### 可优化点
- **状态持久化**：当前通过 history 注入 JSON 实现，建议引入 Redis 独立会话存储，避免 frontend 维护全量 history
- **规则解析模块化**：将 `_parse_chinese_datetime()` 分离为独立时间解析服务，支持更多中文时间表达（"大后天"、"下周X"、"下个月"）

## 3. 数据优化

### 日程分类体系
| 类别 | 类型 | 覆盖 |
|------|------|------|
| 日程内容 | 自由文本 | 不限（用户自定义） |
| 提醒时间 | DATETIME | 精确到分钟 |
| 循环规则 | VARCHAR(100) | 每天/工作日/每周N/一次性 |
| 状态管理 | VARCHAR(20) | active/completed/cancelled |

### 循环规则支持
- **每天 / 每日**：每天同一时间触发
- **工作日 / 周一至周五**：仅工作日触发
- **每周N**：指定星期几触发（如每周一,三,五）
- **一次性（默认）**：仅提醒一次，完成后自动标记 completed

### 中文时间表达覆盖
| 表达 | 识别方式 | 示例 |
|------|----------|------|
| 相对时间 | 正则解析 | "半小时后"、"过一会儿" |
| 日期基准 | 关键词匹配 | "明天"、"后天"、"大后天" |
| 时间段 | 幅/午/晚识别 | "下午5点"、"晚上8点" |
| 分钟表达 | 中文数字识别 | "5点30分"、"5点半" |

### 可优化点
- **循环日程下次触发**：当前仅保留 active，需实现 next_event_time 计算逻辑
- **中文数字全面支持**：如"三点"、"二十一点"、"凌晨一点"
- **节假日跳过**：工作日规则自动跳过法定节假日

## 4. 性能优化

### 模块级延迟分析
| 模块 | 操作 | 预估延迟 | 优化方向 |
|------|------|----------|---------|
| LLM解析 | 意图识别+实体提取 | 500-1500ms | 规则兜底无需网络，<10ms |
| 数据库查询 | CRUD操作 | 10-50ms | 连接池复用，索引优化 |
| 状态管理 | 序列化/反序列化 | <1ms | 当前已高效 |
| 提醒检查 | 到期扫描 | 10-30ms | 添加复合索引(event_time, status) |
| API响应 | 完整请求链路 | 200-1500ms | LLM调用为主瓶颈 |

### 规则兜底 vs LLM
| 对比维度 | LLM解析 | 规则兜底 |
|---------|---------|---------|
| 准确性 | 高（复杂语义） | 中（简单模式） |
| 速度 | 500-1500ms | <10ms |
| 字段覆盖 | 完整8类Intent | 主要4类(add/query/delete/chat) |
| 无需API Key | 否 | 是 |

### 可优化点
- **LLM响应缓存**：高频相同输入可缓存解析结果
- **批量到期检查**：当前 GET /due 每次全表扫描，建议改为定时任务（APScheduler）主动推送
- **连接池优化**：当前 5 连接，高并发场景可调大
