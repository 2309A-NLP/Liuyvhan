# Agent-04 基金问答 — 优化总结

## 一、架构优化

| 优化维度 | 当前实现 | 优化建议 | 优先级 |
|---------|---------|---------|-------|
| **LLM+规则双引擎** | LLM 优先（≥80%），失败回退 12 条规则模板 | 引入 LLM SQL 校验环节（SQL_VALIDATION_PROMPT），在LLM生成后自动校验并重试 | P1 |
| **SQL 自动修复** | 仅修复 ambiguous column + 语法清理 | 扩展修复策略：支持 JOIN 列名自动推导、表别名自动生成 | P2 |
| **缓存层缺失** | 每次重复查询都调 LLM → DB | 新增 SQL 结果缓存（LRU 或简单 dict），同义问题直接命中缓存 | P2 |
| **多表关联优化** | JOIN 语句全部依赖 LLM 或规则模板 | 预计算常见 JOIN 路径模板（如 基金基本信息↔规模变动表），减少 LLM 生成复杂度 | P1 |

## 二、工程优化

| 优化维度 | 当前实现 | 优化建议 | 优先级 |
|---------|---------|---------|-------|
| **超时机制** | ThreadPoolExecutor 60s 超时 | 增加分级超时：LLM 调用 30s → SQL 执行 30s 互不干扰 | P1 |
| **日志级别** | 统一 INFO 级别 | 增加 DEBUG 模式开关，运行时 `--verbose` 显示 SQL 执行详情 | P3 |
| **错误重试** | SQL 失败自动重试 1 次 | 最多重试 3 次，每次使用不同策略（LLM 重生成 → 规则匹配 → 简化查询） | P2 |
| **Web UI 部署** | index.html 通过 FastAPI 静态文件挂载 | 分离前端为独立 SPA 或放到 CDN，减少 API 服务负载 | P3 |

## 三、数据优化

| 优化维度 | 当前实现 | 优化建议 | 优先级 |
|---------|---------|---------|-------|
| **数据库索引** | 无显式索引 | 为 `基金基本信息.基金代码`、`基金类型`、`日行情表.基金代码+日期` 添加索引 | P1 |
| **SQLite 连接** | 每次查询新建连接 | 使用连接池或长连接复用，减少反复开闭连接的开销 | P2 |
| **Schema 缓存** | 懒加载（无过期） | 增加定时刷新机制（每小时检测 DB 文件 mtime） | P3 |
| **问题集管理** | 手动编辑 question.jsonl | 增加 `--add-question` 命令，通过 CLI 录入问题 | P3 |

## 四、性能优化

| 优化维度 | 当前实现 | 优化建议 | 优先级 |
|---------|---------|---------|-------|
| **单次回答** | 耗时 3-8s（LLM + DB） | 降低 LLM temperature 至 0.05，减少 token 输出变化，提升一致性 | P1 |
| **LLM Token 用量** | schema 全部注入（约 3K token） | schema 截断：只注入相关表 schema，减少 50%+ token 开销 | P2 |
| **批量推理** | 串行逐条处理 | 并行处理：用 ThreadPoolExecutor 同时处理多问题（注意 LLM 限速） | P2 |
| **SQL 执行** | 串行单线程执行 | 只读查询可并行执行，聚合查询与明细查询分开 | P3 |

**模块级延迟表（估算）：**

| 阶段 | 耗时 | 占比 |
|------|------|------|
| LLM SQL 生成 | 2-5s | 60% |
| SQL 执行 | 0.2-2s | 20% |
| LLM 回答生成 | 1-2s | 15% |
| 其他（解析/格式化） | 0.1-0.3s | 5% |

## 五、可维护性优化

| 优化维度 | 当前实现 | 优化建议 | 优先级 |
|---------|---------|---------|-------|
| **规则模板** | 代码硬编码 12 条 | 抽取为 YAML/JSON 配置文件，支持热加载和扩展 | P2 |
| **Prompt 管理** | 集中在 prompts.py | 增加版本号管理 + A/B 测试机制 | P2 |
| **单元测试** | 无 | 添加 NL2SQL 规则模板单元测试 + mock LLM 测试 | P1 |
| **数据库兼容** | 仅 SQLite | 抽象 DB 接口层，支持 MySQL/PostgreSQL 切换 | P3 |
| **配置管理** | .env 通过 config.py 加载 | 支持 `python main.py --config custom_config.py` 配置覆盖 | P3 |
