# RAG-工单10 优化总结

## 一、架构优化

### 1.1 CCF竞赛项目架构（与招股书QA项目对比）

| 维度 | RAG-工单10（CCF竞赛） | 之前工单（招股书QA） |
|------|----------------------|-------------------|
| 文档类型 | 上市公司年报（国泰君安/太平洋保险） | 招股说明书（兴图新科/力源信息） |
| Embedding | paraphrase-MiniLM-L12-v2 (384维) | m3e-base (768维) / finetuned-bge-zh |
| Reranker | **关闭**（ENABLE_RERANKER=false） | 开启（bge-reranker-v2-m3） |
| 缓存 | **Redis缓存开启**（TTL 3600s） | 无缓存 |
| 分块策略 | Sliding Window 700/120 | Block-level 分块 |
| 多文档路由 | COMPANY_FILE_HINTS 自动路由 | 双文档手动指定 |
| 数据路径 | `./data/ccf_competition/` | `./data/` |

### 1.2 核心架构流水线（8阶段）

```
用户输入 → Query理解(分类/改写/同义扩展/分解) → 会话记忆 → 混合检索(Vector+BM25) → 多模态图片语义 → 结构化提升 → Redis缓存 → LLM回答
                                                                     ↓
                                                              Reranker: 关闭
```

### 1.3 关键架构决策

- **Reranker关闭**: CCF竞赛场景中，paraphrase-MiniLM 384维嵌入+BM25已能覆盖年报中关键词匹配需求，省略Reranker减少推理开销和启动时间。但评估结果显示FA=0.56偏低，开启Reranker可改善
- **Redis缓存**: 首度引入缓存层，相同问题直接返回缓存结果。TTL 3600s，带conversation_id时跳过缓存（依赖对话上下文）
- **多文档自动路由**: 通过COMPANY_FILE_HINTS（国泰君安→国泰君安证券2021年报,太平洋保险→太平洋保险.pdf）自动选择文档，省去用户手动指定

## 二、工程优化

### 2.1 检索管道

| 阶段 | 策略 | 参数 |
|------|------|------|
| 向量检索 | paraphrase-MiniLM 384维 → Milvus | vector_top_k=8 |
| BM25检索 | 原始问题关键词匹配 | bm25_top_k=8 |
| 混合融合 | V:0.6 + B:0.4 归一化加权 | hybrid_top_k=5, pool=16 |
| Reranker | **关闭** | ENABLE_RERANKER=false |
| 结构化提升 | 14类关键词加分(0.15~0.28) | 关键词/表格/图片/财务/行业 |

### 2.2 Query理解流水线（三独立开关）

```
Step1: 意图分类 (LLM 8类 + 规则兜底)
Step2: 查询改写 (Python规则预处理 → LLM润色)
Step3: 同义扩展 (45条JSON词典 + 8组INTENT_EXPANSION_TERMS)
Step4: 查询分解 (LLM按顿号/和/及拆分)
```

### 2.3 多轮会话记忆

- **ConversationStore**: 内存级OrderedDict，线程安全Lock
- **参数**: 最多10轮，TTL 1800s（30分钟自动过期）
- **省略句/指代还原**: Python规则预处理（"这个公司"替换、"那XX公司呢"继承）、LLM润色

### 2.4 断点续传 + 后台索引

- **Checkpoint**: 启动时从 `.index_checkpoint` 读取索引状态，已完成则跳过
- **后台索引线程**: daemon线程不阻塞uvicorn，Milvus 6次重试
- **BM25恢复**: 启动时从chunks JSON文件恢复BM25索引

### 2.5 多模态图片语义

- **CLIP 16类**: 组织结构图/架构图/流程图/柱状图/趋势图/表格截图等中文标签
- **VLM Qwen3-VL**: 通过SiliconFlow API调用，返回中文描述
- **应用场景**: 年报中的组织结构图、业务流程图、数据图表

## 四、性能优化

### 4.1 RAGAS指标

| 指标 | 分数 | 说明 |
|------|------|------|
| 忠实度 (Faithfulness) | 0.56 | 4/10正确，2题部分正确 |
| 上下文召回率 (Context Recall) | 0.50 | 检索到的chunk中有用内容不足 |
| 上下文精确率 (Context Precision) | 0.48 | 前几篇chunk相关度不足 |
| 答案相关性 (Answer Relevancy) | 0.34 | 纯LLM也偏低（年报数据密集） |

### 4.2 性能瓶颈分析

1. **Reranker关闭**导致检索精度不足：首轮chunk不够精确 → LLM无法回答 → 空返回
2. **paraphrase-MiniLM 384维**语义表示能力有限：年报数据密度高，需要更强embedding
3. **年报非结构化**：国泰君安年报286页，关键数据散落在不同章节，sliding window 700/120粒度不足
4. **纯LLM "幻觉"优势**：纯LLM在4/10问题上出现幻觉（股票交易额19.04万亿、子公司6家），RAG虽然保守但避免了错误数据

### 4.3 优化建议

- 开启Reranker（bge-reranker-v2-m3），预计可提升CR+0.10~0.15
- 更换为m3e-base或微调embedding（768维），提升年报密集数据语义匹配
- 增加chunk size至1000+200，覆盖更完整的年报段落上下文
- 对年报特有的"主要财务指标表"做结构化表提取（类似工单03的表格分块）

## 五、可维护性优化

- **三独立开关**: ENABLE_QUERY_REWRITE/CLASSIFICATION/SYNONYM_EXPANSION 可独立开关，方便调试
- **Redis缓存清理**: 通过force_refresh=true绕过缓存重新生成
- **多文档路由**: 通过COMPANY_FILE_HINTS扩展支持更多年报文档
- **Checkpoint持久化**: 重启后自动恢复索引状态，无需全量重索引
- **Milvus 6次重试**: 应对Docker启动延迟，提升稳定性
