## 常见问题速查

### Q1: Docker 构建失败，提示 "no space left on device"

**原因**：磁盘空间不足  
**解决方案**：

```bash
# 清理 Docker 构建缓存
docker builder prune -a -f

# 清理未使用的镜像、容器、卷
docker system prune -a -f --volumes

# 检查磁盘空间
df -h
```

### Q2: 容器启动后立即退出

**原因**：通常是配置错误或导入异常  
**排查步骤**：

```bash
# 查看退出日志
docker logs rag-app --tail 100

# 临时以交互模式启动，查看完整错误
docker run --rm -it rag-financial-qa:latest python -c "from app.core.config import Settings; s=Settings(); print('配置加载成功')"

# 逐个导入服务模块，定位崩溃点
docker run --rm -it rag-financial-qa:latest python -c "from app.services.llm_service import LLMService; print('LLM 服务加载成功')"
```

### Q3: 应用启动时报 "Connection refused" 连接 Milvus/Redis

**原因**：依赖服务未就绪，应用先启动了  
**解决方案**：

```bash
# 检查依赖服务状态
docker compose ps

# 如果 Milvus 或 Redis 未就绪，等待后重启应用
docker compose restart app

# 查看依赖服务的日志
docker compose logs milvus --tail 50
docker compose logs redis --tail 50
```

### Q4: Milvus 容器反复重启

**原因**：etcd 或 minio 服务未正常启动  
**解决方案**：

```bash
# 重新启动整个 Milvus 栈
docker compose restart milvus-etcd milvus-minio milvus

# 查看 etcd 日志
docker compose logs milvus-etcd --tail 50

# 如果问题持续，重置 Milvus 数据（注意数据丢失！）
docker compose down
docker volume rm rg-工单10_milvus-data rg-工单10_milvus-etcd-data rg-工单10_milvus-minio-data
docker compose up -d
```

### Q5: 问答返回空或错误信息

**原因**：LLM API Key 配置错误、Milvus 未索引数据  
**排查步骤**：

```bash
# 检查 API Key 是否有效
curl -s https://api.siliconflow.cn/v1/models \
  -H "Authorization: Bearer sk-your-key" | head -5

# 检查索引状态
curl http://localhost:8000/api/v1/health

# 检查容器内环境变量
docker exec rag-app env | grep -E "LLM_|MILVUS_|REDIS_"
```

### Q6: 容器内模型加载失败

**原因**：HuggingFace 模型未正确缓存到镜像中  
**解决方案**：

```bash
# 检查缓存目录
docker exec rag-app ls -la /root/.cache/huggingface/

# 如果缓存为空，临时关闭离线模式并手动下载
docker exec -e HF_HUB_OFFLINE=0 -e TRANSFORMERS_OFFLINE=0 rag-app \
  python3 -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2')"

# 然后重启容器
docker compose restart app

# 长期修复：重新构建镜像（在 Dockerfile 中修正模型下载步骤）
docker compose build --no-cache app
```

### Q7: 端口 8000 被占用

**原因**：宿主机已有服务占用了 8000 端口  
**解决方案**：

```bash
# 检查端口占用
netstat -ano | findstr :8000

# 修改 docker-compose.yml 中的端口映射
# 将 "8000:8000" 改为 "8001:8000"（宿主机 8001 -> 容器 8000）
# 然后重新启动
docker compose up -d
```

### Q8: Windows 上运行时路径问题

**原因**：Windows 文件系统权限或路径格式问题  
**解决方案**：

```bash
# 确保项目在 Windows 上时，使用 PowerShell 运行 Docker 命令
# 避免 WSL 路径和 Windows 路径混用

# 将项目放在 C:\ 盘而非 D:\ 盘（D 盘 9p 挂载可能有权限问题）
```

### Q9: Docker 构建非常慢

**原因**：torch 和 sentence-transformers 下载较慢  
**优化建议**：

```bash
# 使用国内镜像加速（修改 Dockerfile）
# 在 pip install 前添加：
# pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 或者使用已下载好的模型缓存
# docker compose build --build-arg BUILDKIT_PROGRESS=plain
```

### Q10: 容器中无法连接外部 LLM API

**原因**：容器网络限制  
**解决方案**：

```bash
# 检查 DNS 配置
docker exec rag-app cat /etc/resolv.conf

# 测试网络连通性
docker exec rag-app curl -s -o /dev/null -w "%{http_code}" https://api.siliconflow.cn

# 如果 DNS 问题，重启 Docker Desktop
```
