## 1. 环境要求

## 3. 部署步骤

### 3.1 准备 .env 配置文件

在项目根目录创建 `.env` 文件，填入以下关键配置：

```bash
# LLM API 配置（必须填写）
LLM_BASE_URL=https://api.siliconflow.cn/v1
LLM_API_KEY=sk-your-api-key-here
LLM_MODEL=deepseek-ai/DeepSeek-V4-Flash
LLM_TEMPERATURE=0

# 可选覆盖
# MILVUS_URI=http://milvus:19530     # Docker 内自动配置
# REDIS_URL=redis://redis:6379/0     # Docker 内自动配置
```

> **注意**：`LLM_API_KEY` 是必填项，没有它服务无法回答金融问题。

### 3.2 放置 PDF 数据文件

将所有金融 PDF 文档放入 `data/raw/` 目录：

```bash
# 示例：将招股说明书放入 raw 目录
cp /path/to/招股说明书1.pdf data/raw/
cp /path/to/招股说明书2.pdf data/raw/
```

### 3.3 构建镜像

```bash
# 进入项目目录
cd RG-工单10/

# 构建 Docker 镜像（首次构建约 10-20 分钟，取决于网络）
docker compose build

# 或单独构建应用镜像
docker build -t rag-financial-qa:latest .

# 查看构建好的镜像
docker images | grep rag-financial-qa
```

> **构建说明**：
> - 镜像包含预下载的 embedding 模型和 CLIP 模型
> - torch 使用 CPU 版本（约 800 MB），适用于无 GPU 环境
> - 首次构建需要联网下载模型，后续构建可使用缓存

### 3.4 启动所有服务

```bash
# 启动所有服务（后台运行）
docker compose up -d

# 查看启动状态
docker compose ps

# 查看实时日志
docker compose logs -f

# 等待所有服务健康检查通过
docker compose ps
# 期望输出：所有服务的 STATUS 列为 "Up (healthy)"
```

**启动顺序**：
1. Milvus 及其依赖（etcd、minio）先启动
2. Redis 启动
3. RAG 应用最后启动，等待 Milvus 和 Redis 就绪

### 3.5 验证服务运行

```bash
# 检查应用健康状态
curl http://localhost:8000/api/v1/health

# 期望响应：
# {"status": "ok", "milvus": "connected", "redis": "connected", ...}

# 检查根路径
curl http://localhost:8000/
# 期望响应：
# {"message": "RAG Prospectus QA API is running", "docs": "/docs"}
```

### 3.6 初始化数据索引

首次部署后，需要让 RAG 服务索引 PDF 文档：

```bash
# 方法一：通过 API 触发索引
curl -X POST http://localhost:8000/api/v1/documents/index

# 方法二：如果后台自动索引已启用（查看日志确认）
docker compose logs -f app
# 搜索 "[INDEX-BG]" 和 "[CHECKPOINT]" 确认索引进度
```

### 3.7 测试金融问答

```bash
# 发送测试问题
curl -X POST http://localhost:8000/api/v1/chat/rag \
  -H "Content-Type: application/json" \
  -d '{
    "question": "请介绍该保险产品的保障范围",
    "session_id": "test-session-001"
  }'

# 期望响应：
# {"answer": "...", "source_documents": [...], ...}
```

## 4. 容器管理

### 4.1 容器启动与停止

```bash
# 启动所有服务
docker compose up -d

# 停止所有服务
docker compose stop

# 停止并删除容器（保留数据卷）
docker compose down

# 停止并删除所有（包括数据卷，数据将丢失！）
docker compose down -v
```

### 4.2 单独管理某个容器

```bash
# 启动/停止/重启应用容器
docker compose start app
docker compose stop app
docker compose restart app

# 进入容器内部（调试用）
docker exec -it rag-app /bin/bash

# 查看容器资源使用
docker stats rag-app
```

### 4.3 使用 docker run 启动单容器

如果需要单独启动应用容器（不使用 docker compose），请确保 Milvus 和 Redis 已运行：

```bash
docker run -d \
  --name rag-app \
  --restart unless-stopped \
  -p 8000:8000 \
  -e MILVUS_URI="http://host.docker.internal:19530" \
  -e REDIS_URL="redis://host.docker.internal:6379/0" \
  -e LLM_API_KEY="sk-xxx" \
  -e LLM_BASE_URL="https://api.siliconflow.cn/v1" \
  -e LLM_MODEL="deepseek-ai/DeepSeek-V4-Flash" \
  -v rag-data:/app/data \
  --network rag-network \
  rag-financial-qa:latest
```

> **注意**：如果 Milvus 和 Redis 在宿主机上直接运行（而非 Docker 中），使用 `host.docker.internal` 替代 `127.0.0.1`。

## 5. 数据持久化

### 5.1 数据卷概览

| 卷名称 | 挂载路径 | 存储内容 | 是否必须备份 |
|--------|---------|---------|------------|
| `rag-data` | `/app/data` | PDF 源文件、chunks、导出结果 | 是 |
| `milvus-data` | `/var/lib/milvus` | 向量数据 | 是 |
| `milvus-etcd-data` | `/etcd` | Milvus 元数据 | 是 |
| `milvus-minio-data` | `/data` | Milvus 日志/快照 | 可选 |
| `redis-data` | `/data` | Redis 持久化数据 | 可选 |

### 5.2 数据持久化说明

所有卷由 Docker 管理，默认存储在：
- Linux：`/var/lib/docker/volumes/`
- Windows：`\\wsl$\docker-desktop-data\data\docker\volumes`

### 5.3 数据备份与恢复

```bash
# 备份 RAG 应用数据
docker run --rm -v rag-data:/source -v $(pwd)/backup:/backup ubuntu tar czf /backup/rag-data-$(date +%Y%m%d).tar.gz -C /source .

# 恢复数据
docker run --rm -v rag-data:/target -v $(pwd)/backup:/backup ubuntu tar xzf /backup/rag-data-20250206.tar.gz -C /target

# 备份 Milvus 数据
docker run --rm -v milvus-data:/source -v $(pwd)/backup:/backup ubuntu tar czf /backup/milvus-data-$(date +%Y%m%d).tar.gz -C /source .
```

### 5.4 容器间数据共享

同一 Docker 卷可以挂载到多个容器。例如，如果需要一个额外的数据处理容器：

```bash
# 创建一个数据处理容器，共享 RAG 数据卷
docker run -it --rm \
  -v rag-data:/app/data \
  --network rag-network \
  python:3.11-slim \
  python3 -c "import os; print(os.listdir('/app/data'))"
```

## 6. 网络配置

### 6.1 网络拓扑

```
┌─────────────────────────────────────────────────────┐
│                  rag-network (bridge)                │
│                                                      │
│  ┌───────────────┐  ┌──────────┐  ┌──────────────┐  │
│  │  rag-app       │  │  redis   │  │  milvus      │  │

│  │                │  │          │  │  │            │  │
│  └───────┬───────┘  └──────────┘  └──────┬─────────┘  │
│          │                                │            │
│          └────────────────────────────────┘            │
```

### 6.2 服务发现

在同一 Docker 网络内，服务通过容器名互相访问：

| 服务名 | 可访问地址 |
|--------|-----------|
| RAG API | `http://app:8000` |
| Milvus | `http://milvus:19530` |
| Redis | `redis://redis:6379/0` |

应用自动配置了这些地址（通过环境变量注入）。

## 7. 与其他服务通信

### 7.1 与外部服务通信

如果 RAG 服务需要与外部服务（如 RTMP 服务器）通信，有两种方式：

**方式一：端口映射（推荐）**

确保外部服务可以访问宿主机的 8000 端口，RAG API 直接暴露出去。

**方式二：加入外部网络**

```bash
# 创建外部网络（如果 RTMP 服务器已运行）
docker network create ext-network

# 将 RAG 应用连接到外部网络
docker network connect ext-network rag-app

# 现在 RAG 应用可以通过 RTMP 服务器的服务名访问它
```

### 7.2 宿主机访问容器

通过 `localhost:8000` 或 `宿主机IP:8000` 即可访问。

## 9. 常见操作

### 9.1 更新部署

当代码有更新时：

```bash
# 拉取最新代码
git pull

# 重新构建并启动
docker compose build app
docker compose up -d
```

### 9.2 重置索引

如果需要清空所有数据并重新索引：

```bash
# 停止服务
docker compose down

# 删除数据卷（谨慎！将丢失所有数据）
docker volume rm rg-工单10_rag-data rg-工单10_milvus-data

# 重新启动
docker compose up -d

# 上传 PDF 并重新索引
# 将 PDF 放入 data/raw/ 后调用索引 API
```

### 9.3 资源限制

如需限制内存和 CPU 使用，在 `docker-compose.yml` 的 app 服务中添加：

```yaml
deploy:
  resources:
    limits:
      cpus: '4'       # 最多使用 4 个 CPU 核心
      memory: 8G      # 最多使用 8 GB 内存
    reservations:
      cpus: '2'       # 预留 2 个 CPU 核心
      memory: 4G      # 预留 4 GB 内存
```

### 9.4 使用 GPU（可选）

如果服务器有 NVIDIA GPU，可以在 docker-compose.yml 中添加：

```yaml
app:
  deploy:
    resources:
      reservations:
        devices:
          - driver: nvidia
            count: all
            capabilities: [gpu]
```

需要安装 NVIDIA Container Toolkit，并将 torch 从 CPU 版本改为 CUDA 版本。
