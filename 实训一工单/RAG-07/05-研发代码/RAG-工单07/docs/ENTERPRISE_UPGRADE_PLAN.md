# 企业级 RAG 升级方案

## 1. 文档目的

本文档用于说明当前《招股说明书1.pdf》问答系统的实际实现状态、与企业级 RAG 项目的能力差距，以及后续优化升级路线。

## 2. 当前项目现状

当前项目已经完成 RAG 主链路，具备可运行、可演示、可评估的基本能力。

### 2.1 已实现能力

- PDF 解析：使用 `pdfplumber` 提取正文与表格
- 文本切块：使用自定义 `ChunkService`
- 向量化：使用 `sentence-transformers` 多语向量模型
- 向量存储：使用 `Milvus`
- 检索问答：使用向量召回 + LLM 生成
- 问答接口：使用 `FastAPI`
- 短期缓存：使用 `Redis`
- 反馈存储：使用 `MySQL` 或本地 `jsonl`
- 效果评估：使用 `RAGAS`

### 2.2 当前架构

```text
PDF -> pdfplumber解析 -> 文本/表格合并 -> Chunk切块 -> Embedding向量化
   -> Milvus存储 -> 相似度检索 -> LLM生成答案 -> FastAPI返回
```

### 2.3 当前存在的问题

- 检索方式单一，当前只有向量检索，没有 BM25 混合检索
- 没有 reranker，召回结果直接送入大模型，证据质量不稳定
- 对招股书类强结构文档缺少章节、目录、表格字段化处理
- Redis 当前用于缓存，不是完整的会话级短期记忆
- Milvus 当前用于文档长期知识存储，不是用户长期记忆
- MySQL 当前只承担反馈落库，不是完整业务数据中心
- 缺少日志、观测、安全治理等企业级基础设施

## 3. 企业级目标架构

### 3.1 目标能力

- 高质量解析 PDF 正文、目录、标题、表格与图片文字
- 混合检索：向量召回 + BM25 关键词召回
- 重排序：使用 `bge-reranker`
- 多轮问答：支持会话短期记忆
- 文档元数据过滤：按章节、年份、页码、表格/正文类型检索
- 可观测：记录检索命中、Token 消耗、时延、异常
- 可评估：具备离线与在线双评估能力
- 可治理：具备权限、安全、密钥与审计管理

## 4. 当前实现与企业实现对比

| 模块 | 当前项目 | 企业标准目标 | 状态 |
| --- | --- | --- | --- |
| PDF解析 | `pdfplumber` 文本+表格抽取 | OCR + 标题识别 + 目录识别 + 表格结构化 | 待增强 |
| 切块 | 固定字符切块 | 章节感知切块 + 表格专用切块 | 待增强 |

## 5. 推荐升级路线

### 5.1 第一阶段：检索效果升级

目标：优先提高问答准确率。

#### 建议内容

- 引入 `BM25` 关键词召回
- 构建混合检索策略
- 引入 `bge-reranker` 重排序
- 提高 `top_k` 与召回候选数配置能力
- 对数字类问题增加查询改写

#### 推荐技术

- BM25：`rank-bm25`
- Reranker：`BAAI/bge-reranker-v2-m3`

#### 预期收益

- 提高财务数字类问题命中率
- 改善章节性问题召回偏差
- 降低大模型“未找到明确答案”的误判概率

### 5.2 第二阶段：文档结构增强

目标：让系统真正理解招股书结构。

#### 建议内容

- OCR 兜底：`PaddleOCR`
- 增加目录、标题、章节识别
- 表格结构化抽取
- 元数据增强：`section_title`、`page`、`chunk_type`、`year`
- 财务表格单独建索引

#### 预期收益

- 支持按章节/年份精准定位
- 提升财务问答和募集资金类问题的召回质量
- 提高可解释性与溯源能力

### 5.3 第三阶段：记忆与业务数据升级

目标：从“单次问答接口”升级为“业务级问答系统”。

#### 建议内容

- Redis 增加 `session_id` 级对话上下文
- MySQL 增加问答日志表、评测结果表、文档任务表
- 反馈闭环：人工评分 -> 数据沉淀 -> 提示词或检索优化

#### 预期收益

- 支持多轮会话
- 支持错误问题分析与持续改进
- 满足业务可追踪性

### 5.4 第四阶段：工程化与治理升级

目标：满足企业上线标准。

#### 建议内容

- 请求日志、检索日志、重排日志
- LLM Token 消耗统计
- 耗时分段监控
- API Key 脱敏与密钥治理
- 审计日志与用户认证
- Docker 化与健康检查

#### 预期收益

- 提升可运维性
- 支持生产部署
- 满足安全要求

## 6. 推荐的企业级技术选型

### 6.1 核心模型与工具

- PDF解析：`pdfplumber`
- OCR：`PaddleOCR`
- 向量模型：生产级中文 embedding 模型
- 向量库：`Milvus`
- BM25：`rank-bm25`
- Reranker：`BAAI/bge-reranker-v2-m3`
- LLM：阿里云百炼 `qwen2.5-7b-instruct`
- 短期记忆与缓存：`Redis`
- 业务数据库：`MySQL`
- 评估：`RAGAS`

### 6.2 目标检索链路

```text
用户问题
  -> Query Rewrite
  -> 向量召回
  -> BM25召回
  -> 召回融合
  -> bge-reranker重排
  -> 取Top-N证据
  -> LLM生成答案
  -> 返回答案与引用页码
```

## 7. 优先级建议

如果时间有限，建议按以下顺序优化：

1. `BM25 + 向量混合检索`
2. `bge-reranker` 重排序
3. `章节与表格元数据增强`
4. `Redis 会话记忆`
5. `日志与评估体系`
