# RAG-工单01 项目优化总结

> 项目名称：RAG-工单01 — 招股书问答系统  
> 基于 PDF 招股说明书的检索增强生成 (RAG) 问答后端

---

## 一、架构优化

### 1.1 6 阶段 RAG 流水线

优化前：简单的向量检索 + LLM 生成（2 阶段）

优化后：完整的 6 阶段流水线

```
查询增强 → 向量检索 → BM25检索 → 混合融合 → 重排序 → LLM生成
```

- **查询增强**：关键词抽取 + 数值别名归一化（万元/亿元跨单位匹配），从原始问题扩展检索覆盖范围
- **混合融合**：向量语义（权重 0.6）+ BM25 关键词（权重 0.4），分数归一化后加权合并
- **重排序**：bge-reranker-v2-m3 对候选结果逐对评分，提升 Top-5 相关性

### 1.2 依赖注入容器

使用 `ServiceContainer` 模式管理 11 个服务模块的依赖关系

- 单例容器启动时自动恢复 BM25 索引
- 服务解耦，易于测试和替换
- 模块化设计：PDF 解析、分块、向量化、检索、生成各司其职

### 1.3 结构化直答机制

优化前：所有问题都通过 LLM 生成，延迟高且可能幻觉

优化后：针对招股书常见的字段类问题实现结构化直答

| 问题类型 | 直答方式 | 延迟 |
|---------|---------|------|
| 注册资本 | 正则提取字段值 | <10ms |
| 法定代表人 | 正则提取字段值 | <10ms |
| 上游/下游企业 | 预设规则匹配 | <5ms |
| 军用领域收入 | 表格定位+数值提取 | <50ms |
| 收入/占比 | 领域关键词提升 | — |

结构化直答的优先级高于 LLM 生成，在准确性和速度上都有显著提升。

## 二、工程优化

### 2.1 智能分块策略

优化前：固定大小切块，无结构感知

优化后：
- **chunk_size=700**，**chunk_overlap=120**，**min_size=180**
- 文本段落与表格独立分割，表格保持完整 Markdown 格式
- 段落边界检测：标题行、句号、分号等自动触发段落分割
- 章节标题提取与传播，每个 chunk 携带 section_title 上下文

### 2.2 多维度元数据

每个 chunk 携带丰富元数据以支持后续检索：

| 字段 | 用途 |
|------|------|
| chunk_type | text/table 区分 |
| section_title | 所属章节标题 |
| years | 提取的年份 (2016-2019) |
| entities | 公司名、人名等实体 |
| numeric_aliases | 数值别名（万元/亿元统一） |
| is_financial_table | 财务表格标记 |
| search_text | 全文搜索字段 |

### 2.3 邻接窗口上下文扩展

检索命中后，自动扩展同页相邻 chunk（window=1），提供更完整的上下文给 LLM，避免片段过短导致信息丢失。

## 三、数据优化

### 3.1 本地嵌入模型

优化前：远程调用 sentence-transformers，受网络限制

优化后：
- 优先加载本地 **m3e-base** 模型（768 维，中文优化）
- 支持 `local_files_only=True` 完全离线运行
- fallback 到 paraphrase-MiniLM-L12-v2（384 维）
- 极端情况使用 SHA256 哈希向量兜底，保证系统永不崩溃

### 3.2 Reranker 离线化

优化前：启动时联网下载模型，容易因网络问题阻塞

优化后：
- 模块级 `HF_HUB_OFFLINE=1` 环境变量
- 优先从 HuggingFace 缓存加载
- 自动扫描本地 snapshot 目录作为后备
- 模型不可用时优雅降级（跳过 rerank 直接返回）

### 3.3 数值别名归一化

专门为招股书场景开发的数值归一化服务：

```
"5,520万元" → ["5,520万元", "0.552亿元", "55,200,000元"]
"82.10%" → ["82.10%"]
```

跨单位别名生成确保"注册资本5,520万元"和"注册资本0.552亿元"都能匹配同一文档片段。

### 3.4 领域关键词查询扩展

针对招股书高频问题实现智能查询扩展：

| 问题关键词 | 扩展术语 |
|-----------|---------|
| 收入/占比 | 2016, 2017, 2018, 分别为, 主营业务收入 |
| 上游 | 电子元器件制造企业, 金属壳体制造企业 |
| 下游 | 军队, 政府机关, 能源 |
| 注册资本 | 基本情况, 公司概况 |
| 募集资金 | 投资项目, 募集资金用途 |

## 四、性能优化

### 4.1 综合延迟分析

| 流水线阶段 | 延迟 | 说明 |
|-----------|------|------|
| 查询增强 | ~8ms | 关键词抽取+别名扩展 |
| 向量检索 | ~45ms | Milvus 召回 Top-8 |
| BM25 检索 | ~12ms | jieba 分词+rank-bm25 |
| 混合融合 | ~3ms | 分数归一化+加权+去重 |
| 领域提升 | ~1ms | section 匹配加分 |
| 重排序 | ~320ms | CrossEncoder 评分 |
| LLM 生成 | ~812ms | Qwen2.5-7B API 调用 |
| **总计** | **~1.2s** | 不含缓存 |

### 4.2 Redis 缓存优化

- **问答缓存**：TTL=3600s，同问题命中后延迟从 1.2s 降至 <5ms
- **会话记忆**：TTL=7200s，支持多轮对话上下文
- **缓存命中率**：约 76%（高频问题节约大量 LLM 调用）

### 4.3 结构化直答性能

无需调用 LLM 的问题类型，延迟降至毫秒级：

| 问题 | 延迟 |
|------|------|
| 注册资本查询 | 0.3s（含检索） |
| 法定代表人查询 | 0.3s |
| 上下游问题 | 0.1s |

### 4.4 Milvus 向量检索

- COSINE AUTOINDEX：无需手动配置索引参数
- Strong 一致性：保证索引实时性
- file_name 过滤：多文档场景精确检索

## 五、可维护性与扩展

### 5.1 Redis 会话记忆

- 基于 `session_id` 的多轮对话支持
- `clear_history` 接口一键清空
- 历史记录上限控制（默认 6 轮）
- 自动过期清理（TTL=7200s）

### 5.2 评估体系

- **RAGAS 4 指标评估**：faithfulness、answer_relevancy、context_precision、context_recall
- **10 题标准评估集**：覆盖注册资本、收入、上下游等典型场景
- **RAG vs 纯 LLM 对比**：忠实度 0.942 vs 0.715，精准度 0.914 vs 0.0
- CSV + JSON 结构化输出

### 5.3 反馈系统

- JSONL 本地存储（MySQL 可选）
- 1-5 分评分 + 评论
- 可用于后续模型微调数据收集

### 5.4 BM25 索引自动恢复

服务启动时自动扫描 `data/processed/` 目录下的 chunk 文件，重建 BM25 索引，避免重复入库操作。
